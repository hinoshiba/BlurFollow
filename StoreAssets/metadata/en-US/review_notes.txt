BlurFollow is a macOS visual masking utility with no login or proprietary account. Free creation allowances are independent: 10 Display Pins, 5 Window Pins, and 2 Text Follow (Beta) rules. Only new creation is gated; existing items are never removed or disabled.

“Beta” labels only the maturity of this optional, non-expiring OCR feature. BlurFollow and its distribution are complete, not beta, demo, trial, or time-limited software.

Core and Text Follow (Beta) review flow
1. Complete onboarding. Create a Display Pin by dragging on the selection overlay; this mode needs no Screen Recording permission.
2. Create a Window Pin, select a non-sensitive test window in Apple's picker, and confirm the mask follows window movement and resizing.
3. Show “BlurFollow Test 123” in two blocks. Create Prefix “BlurFollow Test,” select that window, and verify both Mosaics update while counting as one rule. Also test Exact, Contains, and Regular Expression. Contains “Test 123” is case-sensitive and must mask the whole Vision block, not just the substring. Regex example: `BlurFollow Test [0-9]+`.
4. Text Follow (Beta) uses on-device Vision OCR. Fonts, size, contrast, language, motion, scrolling, and layout can cause misses, false matches, splitting, merging, or delay. It is separate from Window Pin and does not identify confidential content.
5. Open Share Preview for the same window and verify Window Pins plus completed Text Follow (Beta) matches. With “Strict Safety: Protect the Whole Window” on, changing/removing matches must cover recognition, uncertainty, and completed zero matches. Turn it off: prior desktop masks remain during uncertainty and a coherent zero-match preview may render, avoiding full-window flash but reducing OCR-miss resistance. Unready/failed Preview states still clear and fully cover. Reconnect after relaunch. OCR/preview exclude child windows; zero never proves completeness.
6. Desktop Mosaic pixelates the actual backdrop with Core Image; if that filter is unavailable, the region becomes opaque rather than leaving readable source visible.

Independent gate and purchase flow
1. Before purchasing, save 10 Display Pins, 5 Window Pins, and 2 Text Follow (Beta) rules. Enabled and disabled items both count; simultaneous matches do not add rule count.
2. Request an 11th Display Pin: the offer appears before range selection. Cancel it.
3. Request a 6th Window Pin: the offer appears before Apple's picker. Cancel it.
4. Request a 3rd Text Follow (Beta) rule: the offer appears before the rule creator. Complete the purchase with the review account; the creator resumes. Enter a valid rule and choose its window in Apple's picker. The other categories' usage does not change a category's gate.
5. Quit/relaunch, verify unlimited creation, then use Settings → Support BlurFollow → Restore Purchases. StoreKit cancellation, pending, or failure does not grant access.

Permissions and data handling
• macOS 15.2+: Apple's picker authorizes each selected window. macOS 14–15.1: broader Screen Recording permission and an app reopen are required. Denial stops window-dependent features rather than guessing.
• Share Preview and Text Follow (Beta) process selected-window frames on device, video only. Frames and recognized candidate strings are not written to files or sent to the developer. Saved patterns, mask/rule settings, and limited window identity metadata are stored locally. There are no analytics or advertising SDKs.
• No Accessibility, Full Disk Access, camera, or microphone permission is requested.

Any fabricated test window can be used. Always visually inspect both BlurFollow's output and the receiving application's preview; status does not certify content.
